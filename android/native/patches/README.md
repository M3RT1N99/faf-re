# The engine files the Android build compiles changed

Each `<path>.patch` is a `git diff` of the engine file `<path>`, applied to a copy at configure time
(`../cmake/FafAndroidOverlay.cmake`, `../README.md`). The repository's files stay as they are.

| File | Change | Why there is no other way |
|---|---|---|
| `src/gpg/gal/Device.cpp` | The device factory and `SupportsVertexTextureFormat` without the Direct3D 9 to 12 cases and their includes | The factory names every backend's class; Android has the Vulkan backend alone |
| `src/gpg/gal/backends/vulkan/DeviceVulkan.cpp` | The swap chain takes R8G8B8A8 where the window has no B8G8R8A8; copies between the two orders blit, readbacks swap red and blue; the swap chain's usage is what the surface supports; its pre-transform is the identity; a device without BC textures comes up and holds BC1-3 textures as R8G8B8A8: uploads decode them on the CPU (`src/gal/BlockCompressionAndroid.cpp`, WARP's decode), readbacks compress them again; the engine still sees the BC format | Android's window surfaces have no B8G8R8A8, and phones' GPUs mostly lack BC (the Galaxy S22's Xclipse 920 has ETC2 and ASTC); the UI's texture sheets are BC3 textures the engine fills itself, which no codec sees. A phone's panel is portrait: the engine draws upright, and with the surface's current transform the compositor would show the image turned, on a landscape screen also squeezed |
| `src/gpg/gal/backends/vulkan/DeviceVulkan.cpp`, `DeviceVulkan.h` (the surface) | `TestCooperativeLevel` lets go of a surface that went, or a swap chain that failed, and takes the next surface: a new `VkSurface` and swap chain, whose images the back buffer target takes. Until then it answers 2, what would draw on the back buffer draws nowhere, and the engine's objects stay; only a new size goes through 1 and `InitContext`. `Setup` waits for a surface, and `Present` says that a frame went out | An activity's surface goes when it goes to the back, nothing may use it after `surfaceDestroyed` returns (`Win32Android_SetScreenSurface`), and a window takes one `VkSurface` at a time; a Windows program's window stays |
| `src/gpg/gal/backends/vulkan/ResourcesVulkan.cpp`, `ResourcesVulkan.h`, `DeviceVulkan.cpp`, `DeviceVulkan.h` (the draws) | A dynamic buffer's copy in upload memory holds what is locked and what draws read (`PrepareDraw` works it out, an indexed draw's from its indices), with the last values, where it held the whole buffer | The UI's batches lock 0x8000 vertices' buffer for a few each, many times a frame: the menu ran at 10 fps on the emulator. Not Android's own, a candidate for the engine, with `BufferStorageD3D12` |
| `src/moho/misc/StartupHelpers.cpp` | `USER_SavePreferences` opens its stream with `/` for `\` | The path has Windows' separators, which the engine's POSIX layer converts in its Win32 functions; a C++ stream takes them for part of a file name, so `Game.prefs` was never written |
| `src/gpg/gal/backends/vulkan/VulkanLoader.cpp` | Opens `libvulkan.so` | The loader names `vulkan-1.dll`, and the engine's POSIX `LoadLibraryA` is a plain `dlopen` |
| `src/gpg/gal/D3D9Utils.h` | Includes `<d3d9types.h>` where the stand-ins provide it | The gal interfaces take a `D3DVIEWPORT9`; the header includes the type on Windows only |
| `src/moho/render/ID3DTextureSheet.h` | The same, instead of its own `RECT` and `D3DLOCKED_RECT` | Its own `RECT` clashes with the one the engine's POSIX `Windows.h` defines, which the client's files include as well |
| `src/moho/terrain/HighFidelityTerrain.cpp`, `LowFidelityTerrain.cpp`, `MediumFidelityTerrain.cpp`, `water/Shoreline.cpp` | The render-stat counters cast to `platform::InterlockedLong*` | They cast a 32-bit field to `long*`, which is 64-bit on Android; the engine's `platform::InterlockedLong` (`src/platform/Interlocked.h`) is its own type for this cast, as its simulation code uses it |
| `src/moho/audio/CUserSoundManager.cpp`, `app/CScApp.cpp`, `app/WxRuntimeTypes.cpp`, `render/d3d/CD3DDevice.cpp`, `ui/UiRuntimeTypes.cpp` | The stat counters cast to `LONG*`, Win32's 32-bit type, for the Win32 `Interlocked*` functions | The same `long*` cast of a 32-bit field; the engine's POSIX layer declares these functions with `LONG`, as Win32 does |
| `dependencies/boost_1_34_1/libs/thread/src/mutex.cpp` | `boost::mutex` is recursive | On Windows boost 1.34's mutex is a critical section, which the thread that holds it may take again, and the engine's code relies on that (`STAT_GetLuaTable` holds a stat's lock while `StatItem::ToLua` takes it again, every UI frame); a POSIX mutex deadlocks there |
| `src/moho/console/ClientConCommands.cpp` | `EFX_CreateEmitterWindow` says in the log that the build has no emitter editor; the selection helper only it used goes | The command creates the editor, `WEmitterWx`, a wx tool window that wx-lite leaves out (`../WX_LITE.md`); a stand-in for its constructor would need the whole frame class |

`src/moho/render/ID3DTextureSheet.cpp` and `src/gpg/gal/backends/vulkan/GpuDrivenVulkan.cpp` are
compiled from the overlay as well, unchanged: they include their patched headers by their bare names,
which would find the unpatched ones next to them.
